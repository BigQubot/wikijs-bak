= 简介

Banana Pi BPI-CM4 采用 Amlogic A311D 设计，配备四核 ARM Cortex-A73 与双核 ARM Cortex-A53 CPU、ARM G52 MP4（6EE）GPU，以及算力为 5.0 TOPS 的 AI NPU。它支持摄像头和 MIPI-CSI 接口、HDMI 输出及两个千兆网口，并配有 4 GB RAM 和 16 GB eMMC 闪存。

TIP: 更多信息： link:/en/BPI-CM4/BananaPi_BPI-CM4[Banana Pi BPI-CM4]

= 开发准备

. 准备一根 USB 转串口线和一个 5 V/3 A Type-C 电源适配器。串口线用于控制台调试，Type-C 数据线用于下载 Android 镜像和 ADB 调试。
. Linux 开发需要一张至少 8 GB 的 SD 卡；Android 仅支持从 eMMC 启动。
. SoC ROM 首先尝试从 eMMC 启动。因此，只要 eMMC 中存在可启动镜像，开发板就无法从 SD 卡启动。更多信息请参阅开发板的 link:/en/BPI-CM4/GettingStarted_BPI-CM4#_boot_sequence[启动顺序]。

**构建使用指定默认 DTBO 的 Android 镜像**

. 默认内置 Overlay 定义在 device/bananapi/bananapi_m2s/Kernel.mk 中，可以在此处添加新的 DTBO Overlay。
+
```sh
 DTBO_DEVICETREE := android_p_overlay wifi_bt_rtl8822cs i2c1 i2c2 sdio uart1 uart1_cts_rts uart2 hifi_pcm5122
```
. 默认应用的 DTBO idx 定义在 device/bananapi/bananapi_m2s/BoardConfig.mk 中，可以修改 idx 值来选择默认应用的 DTBO Overlay。
+
```sh
 BOARD_KERNEL_CMDLINE += androidboot.dtbo_idx=0
```
. DTS 文件位于 common/arch/arm64/boot/dts/amlogic/overlay/bananapi_m2s/
+
有关 Android 设备树 Overlay 的更多信息，请参阅 link:https://source.android.com/devices/architecture/dto[Android 官方文档]。

== 将镜像写入 SD 卡
> 使用 Balena Etcher 写入镜像，支持 Windows、Linux 和 macOS。

link:https://balena.io/etcher[Balena Etcher] 是 Balena 提供的开源图形化镜像写入工具，可将操作系统镜像写入 SD 卡或 U 盘。

- 单击“Flash from file”以选择镜像。 
- 单击“Select target”选择目标设备。
- 单击“Flash!”开始写入。

image::/picture/etcher.jpg[etcher.jpg]

> 使用 Balena CLI 写入镜像，支持 Windows、Linux 和 macOS。

link:https://github.com/balena-io/balena-cli[Balena CLI] 是 balenaCloud/openBalena 的命令行工具，可用于写入 Linux 镜像。从 link:https://github.com/balena-io/balena-cli/releases[balena-io Releases]下载安装程序或独立软件包，并按照 link:https://github.com/balena-io/balena-cli/blob/master/INSTALL.md[安装说明]正确安装到 PC。随后可使用 Balena 的“link:https://docs.balena.io/reference/balena-cli/#local-flash-image[local flash]”命令将 Linux 镜像写入 SD 卡或 U 盘。
```sh
 $ sudo balena local flash path/to/xxx-bpi-m2s-xxx.img.zip
 $ sudo balena local flash path/to/xxx-bpi-m2s-xxx.img.zip --drive /dev/disk2
 $ sudo balena local flash path/to/xxx-bpi-m2s-xxx.img.zip --drive /dev/disk2 --yes
```

> 在 Linux 中使用 dd 命令写入镜像

如果 SD 卡设备 /dev/sdX 的分区已自动挂载，请先将其卸载。bpi-copy 的实际写入方式与此 dd 命令相同。
```sh
 $ sudo apt-get install pv unzip
 $ sudo unzip -p xxx-bpi-cm4-xxx.img.zip | pv | dd of=/dev/sdX bs=10M status=noxfer
```
> 在 Linux 中使用 bpi-tools 写入镜像 

将 SD 卡插入 Linux PC，然后运行：
```sh
 $ sudo apt-get install pv unzip
 $ sudo bpi-copy xxx-bpi-cm4-xxx.img.zip /dev/sdX
```

== 安装镜像到 eMMC

. 准备一张已写入 Linux 镜像的 SD 卡，并用该 SD 卡启动开发板。
. 将 Linux 镜像复制到 U 盘，将 U 盘插入开发板并挂载。
. 可通过以下两种方式将 Linux 镜像安装到开发板。
- 使用 dd 命令安装。如果 mmcblk0p1 和 mmcblk0p2 分区已自动挂载，请先卸载。bpi-copy 的实际作用与这里的 dd 命令相同。
+
```sh
 $ sudo apt-get install pv unzip
 $ sudo unzip -p xxx-bpi-cm4-xxx.img.zip | pv | dd of=/dev/mmcblk0 bs=10M status=noxfer
```
- 使用 bpi-tools 命令安装 U 盘中的 Linux 镜像
+
```sh
 $ sudo apt-get install pv unzip
 $ sudo bpi-copy xxx-bpi-cm4-xxx.img.zip /dev/mmcblk0
```
. 下载完成后，安全关闭电源并弹出 SD 卡。

== DTB Overlay
. DTB Overlay 用于配置 40 Pin GPIO 的复用功能，文件位于 VFAT 启动分区中。可使用 mount 命令查看挂载点。
+
```sh
 root@bananapi:~# ls /boot/overlays/
 custom_ir.dtbo      pwm_b-backlight.dtbo  spi0.dtbo
 ds3231.dtbo         pwm_c-beeper.dtbo     uart1_cts_rts.dtbo
 hifi_pcm5102a.dtbo  pwm_cd-c.dtbo         uart1.dtbo
 hifi_pcm5122.dtbo   pwm_cd.dtbo           uart2.dtbo
 i2c1.dtbo           pwm_ef.dtbo           waveshare_tft24_lcd.dtbo
 i2c2.dtbo           pwm_ef-f.dtbo         waveshare_tft35c_lcd.dtbo
 pwm_ab.dtbo         sdio.dtbo             waveshare_tft35c_rtp.dtbo
```
. 修改 VFAT 分区中的 /boot/env.txt，通过 overlays 环境变量启用所需功能。
+
```sh
 # Device Tree Overlays
 #   uart1           -- Enable UART1 (uart_A, GPIO Header PIN8 & PIN10)
 #   pwm_c           -- Enable PWM_C (GPIO Header PIN7)
 #   i2c2            -- Enable i2c2 (GPIO Header PIN3 & PIN5)
 #   spi0            -- Enable SPI0 (GPIO Header PIN19 & PIN21 & PIN23 & PIN24)
 overlays="i2c2 spi0 uart1"
```
. 修改后必须重启开发板，DTB Overlay 才会加载。

== 启用相机
Linux 发布镜像默认未启用摄像头，可按以下步骤启用。

. 修改 /boot/env.txt 中的 link:/en/BPI-CM4/GettingStarted_BPI-CM4#_dtb_overlay[DTB Overlay] 配置，启用摄像头 DTBO。
+
```sh
 overlays="os08a10"
```
. 将摄像头模块添加到 /etc/modules
+
```sh
 iv009_isp_iq
 iv009_isp_lens
 iv009_isp_sensor
 iv009_isp
```
. 创建 /etc/modprobe.d/os08a10.conf，并添加摄像头模块选项
+
```sh
 #choose camera calibration parameters
 options iv009_isp_iq cali_name=0
 #choose isp register sequence
 options iv009_isp_sensor isp_seq_num=0
``` 
. 启用摄像头 ISP systemd 服务
+
```sh
 $ sudo systemctl enable camera_isp_3a_server.service
```
重启后，摄像头设备为 /dev/video0。

== 切换 MIPI 面板
默认 Linux 发布镜像一次仅支持一种 MIPI 面板，因为硬件在启动时无法检测不同的面板。系统默认启用 800×1280 BPI 面板，也可在 /boot/lcd_env.txt 中将默认面板改为 1200×1920 BPI 面板。
```sh
 # Mipi panel type
 #    Symbol    | Resolution
 # ----------------------+-------------
 #    "lcd_0"   | 10" 800x1280 panel
 #    "lcd_1"   | 10" 1200x1920 panel
 panel_type=lcd_0
```
WARNING: Linux 不支持双屏同时显示，因此使用 MIPI 面板时请断开 HDMI 线缆。

== 面板旋转
两款 10 英寸 MIPI 面板在硬件上均为竖屏，因此发布镜像默认为竖屏模式，也可以旋转 90、180 或 270 度。 +
对于桌面镜像，创建 Xorg 配置文件 /usr/share/X11/xorg.conf.d/10-fbdev-rotate.conf，内容如下：

== 从 SSD 启动 Linux
A311D SoC ROM 和 link:https://github.com/BPI-SINOVOIP/BPI-M2S-bsp[BPI-M2S-bsp] 的 U-Boot 均不支持从 NVMe 启动。因此，要从 SSD 运行 Linux，必须先在 SD 卡或 eMMC 中写入引导加载程序和启动分区，再从 SSD 加载根文件系统。启动完成后，系统将从 SSD 运行。由于 Banana Pi CM4IO 板载的是 Mini PCIe 插槽，因此还需要一块 Mini PCIe 转 NVMe 适配板。

. 最简单的方法是将 link:/en/BPI-CM4/GettingStarted_BPI-CM4#_install_image_to_sdcard[CM4 Linux 镜像写入 SD 卡或 eMMC]，用于引导系统；同时将该镜像写入 NVMe SSD，用于加载根文件系统。
. 使用 link:/en/BPI-CM4/GettingStarted_BPI-CM4#_boot_sequence[SD 卡或 eMMC] 启动 CM4，然后修改 /boot/boot.ini，让内核从 NVMe 分区加载根文件系统。
+
```sh
 diff a/boot/boot.ini b/boot/boot.ini
 index 2222e79..c485067 100755
 --- a/boot/boot.ini
 +++ b/boot/boot.ini
 @@ -20,6 +20,8 @@ fi;

  if test "${devtype}" = "usb"; then setenv rootfsdev "/dev/sda2"; fi

 +# force set root=/dev/nvme0n1p2
 +setenv rootfsdev "/dev/nvme0n1p2"
 +
  # Load env.txt
  fatload ${devtype} ${devno}:1 ${env_loadaddr} env.txt
  env import -t ${env_loadaddr} ${filesize};
```
. 重启系统，内核将从 NVMe SSD 加载根文件系统。
+
image::/picture/cm4_ssd_rootfs.png[cm4_ssd_rootfs.png]

. 极端情况下，引导加载程序或 U-Boot 已损坏：ROM 从 eMMC 加载后，启动过程停在 U-Boot 或 BL2。例如 DRAM 初始化失败时，eMMC 启动会停在 BL2。此时只能使用 USB Burning Tool 格式化 eMMC，或者完整写入 Android 镜像后，再尝试其他方法擦除 eMMC 或写入 Linux 镜像。

. 如果 eMMC 为空，ROM 会尝试直接从 SD 卡加载引导加载程序。
使用 dd 命令擦除 eMMC 中的 Android 数据
如果开发板之前写入过 Android，而现在要从装有 Linux 镜像的 SD 卡启动，则必须使用以下命令擦除整个 eMMC。
+
```sh
 $ sudo dd if=/dev/zero of=/dev/mmcblk0boot0 bs=1M status=noxfer 
 $ sudo dd if=/dev/zero of=/dev/mmcblk0boot1 bs=1M status=noxfer
 $ sudo dd if=/dev/zero of=/dev/mmcblk0 bs=1M status=noxfer 
 $ sync
```

== 启用 rc-local
发布镜像中已包含 systemd 服务 rc-local.service，但其单元文件缺少 [Install] 部分，因此 systemd 无法启用该服务。首先需要更新该文件。
```sh
 $ sudo nano /lib/systemd/system/rc-local.service
```
```sh
 [Unit]
 Description=/etc/rc.local Compatibility
 Documentation=man:systemd-rc-local-generator(8)
 ConditionFileIsExecutable=/etc/rc.local
 After=network.target
 
 [Service]
 Type=forking
 ExecStart=/etc/rc.local start
 TimeoutSec=0
 RemainAfterExit=yes
 GuessMainPID=no
 
 [Install]
 WantedBy=multi-user.target
 Alias=rc-local.service
```
创建 /etc/rc.local 文件：
```sh
 sudo nano /etc/rc.local
```
```sh
 #!/bin/sh
 #
 # rc.local
 #
 # This script is executed at the end of each multiuser runlevel.
 # Make sure that the script will "exit 0" on success or any other
 # value on error.
 #
 # In order to enable or disable this script just change the execution
 # bits.
 #
 # By default this script does nothing.
 
 exit 0
```
为 /etc/rc.local 添加可执行权限：
```sh
 $ sudo chmod +x /etc/rc.local
```
启用 rc-local.service 并重启：
```sh
 $ sudo systemctl enable rc-local.service
 $ sudo reboot
```

== 安装 Docker Engine
在 Ubuntu 20.04 Server 上安装 Docker Engine。

. 设置软件仓库
+
更新 apt 软件包索引，并安装使 apt 能够通过 HTTPS 使用软件仓库的软件包：
+
```sh
 $ sudo apt-get update
 $ sudo apt-get install apt-transport-https ca-certificates curl gnupg lsb-release
```
添加 Docker 官方 GPG 密钥：
+
```sh
 $ curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg
```
设置 stable 软件仓库：
+
```sh
 $  echo \
    "deb [arch=arm64 signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] https://download.docker.com/linux/ubuntu \
    $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
```
. 安装 Docker Engine
+
```sh
 $ sudo apt-get update
 $ sudo apt-get install docker-ce docker-ce-cli containerd.io
```
. 运行 hello-world 镜像，验证 Docker Engine 是否安装正确。
+
```sh
 $ sudo docker run hello-world
```
+

也可以使用一条命令安装 Docker：
+
```sh
 $ curl -sSL get.docker.com | sudo sh
```
